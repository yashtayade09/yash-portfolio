Templates are organized under `templates/dashboard/` with a strict inheritance hierarchy: `base.html` defines the full HTML shell (sidebar navigation, topbar, theme toggle, toast container) and exposes `{% block %}` slots (`title`, `page_title`, `page_subtitle`, `page_actions`, `content`, `extra_css`, `extra_js`). Concrete pages (`home.html`, `profile.html`, `settings.html`, `login.html`, `hero.html`) extend this base. Reusable CRUD scaffolding is provided by `generic_list.html` and `generic_form.html`, which expect context variables like `model_name`, `items`, `has_order`, `list_url`, and `item` so that view code can render any model's index/edit pages uniformly. `_form_fields.html` holds reusable field fragments. The sidebar menu is hard-coded in `base.html` using Django `{% url %}` tags keyed to named URLs (e.g. `manage_profile`, `manage_hero_roles`, `manage_messages`), establishing a contract between templates and URLconf. Static assets live in `static/dashboard.css` (scoped with a `db-` BEM-like prefix) and `static/dashboard.js`, which is loaded at the bottom of `base.html`. The JS file is an IIFE that bootstraps independent features (theme persistence via `localStorage`, sidebar drawer/collapse, auto-dismissing toasts, animated counters, client-side table search, confirmation dialogs, password visibility toggles, and a command-palette-style quick-jump overlay) — each feature guards against missing DOM nodes before attaching listeners.
