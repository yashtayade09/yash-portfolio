Single Django application (`apps.py` defines `PortfolioConfig`) organized in standard Django layout. `models.py` declares all domain entities: `Profile`, `HeroRole`, `Education`, `Experience`, `Skill`/`SkillCategory`, `Technology`, `Certificate`, `Workshop`, `Project`/`ProjectCategory`/`ProjectImage`, `Achievement`, `Service`, `Resume`, `SocialLink`, `ContactMessage`, and `SiteSettings`; most models share common ordering via `display_order` and visibility toggles (`is_active`/`is_visible`). `forms.py` and `forms_extended.py` provide thin `ModelForm`s (mostly `fields = '__all__'`) bound to each model. `views.py` is the central controller: a single `generic_crud` helper drives list/add/edit/delete for every content module through tiny wrapper views, plus dedicated handlers for profile, hero roles, settings, and a contact-message inbox; two public endpoints expose data — `portfolio_api` returns a consolidated JSON payload of all portfolio sections, and `contact_api` accepts POSTed messages. `urls.py` wires routes under `/`, `/admin-login*`, `/dashboard/*`, and `/api/*`. A `context_processors.dashboard_globals` injects unread message counts into templates, and a `templatetags/dashboard_extras` provides custom template tags. The app uses Django's built-in auth (`@login_required`) for dashboard protection and serves the static `index.html` directly from `settings.BASE_DIR` for the public home page.
